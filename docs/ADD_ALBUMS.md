# 添加专辑

本教程说明如何从一个空克隆添加有权使用的音频，并在本地预览。专辑目录自动发现，不用去 React 组件里逐张注册。

## 放置位置

audio/ 的每个直接子目录代表一张专辑。专辑目录内可以有任意层级的子目录；扫描器会递归寻找媒体文件。

~~~text
audio/
└── paper-moons/
    ├── album.json
    ├── artwork/
    │   ├── cover.webp
    │   └── presentation.webp
    ├── Disc 1/
    │   ├── 01-Quiet-Harbor.flac
    │   └── 02-Blue-Window.flac
    └── Lyrics/
        ├── quiet-harbor.lrc
        └── blue-window.lrc
~~~

上面的艺人、专辑和曲名均为虚构示例。不要将没有再分发授权的商业录音、歌词或图片放入公开仓库。audio/ 已由 .gitignore 排除。

每个音频专辑都应直接放在 audio/ 下，例如 audio/paper-moons/。若使用 audio/艺人名/专辑名/，扫描器会把艺人名这一层当作专辑目录，而不是继续把每个孙目录当作单独专辑。

## 是否要写 album.json

可以不写。扫描器会从曲目文件名和可读取的音频标签推导曲名、艺人、年份、流派与排序。建议新专辑仍然写 album.json 并显式设置稳定的 ASCII id，因为它可以固定显示名称、日期、颜色和文案，也能避免改文件夹名称时改变远端身份。字段说明见 [ALBUM_METADATA.md](ALBUM_METADATA.md)。

如果没有任何媒体，只有包含字段的 album.json 也会被扫描为一张空专辑；但 music:sync 拒绝发布零张专辑的 Catalog。

## 支持的文件格式

扫描器实际支持以下扩展名：

| 类型 | 格式 |
| --- | --- |
| 音频 | .mp3、.m4a、.aac、.ogg、.opus、.wav、.flac |
| 外部歌词 | .lrc |
| 图片 | .jpg、.jpeg、.png、.webp、.avif |

扩展名需要和文件实际格式一致。曲库音频可以是完整曲目，也可以是用户合法持有的试听音频；项目不会从网络下载曲目。

## 子目录与多碟

专辑目录内允许多层子目录，例如 Disc 1、Disc 2、Bonus/Disc 2。路径段中出现独立的 Disc、Disk 或 CD 加数字时，扫描器会尝试提取碟号。音轨号从文件名或子目录段开头的 1 到 3 位数字推导，例如 01-、02.、3_。建议把碟号和音轨号同时写清楚，重复曲名也更容易区分。

full/、generated/ 和 cache/ 是音频根目录的保留名称，不要把新专辑放在其中。旧版 audio/full/<专辑名>/ 有兼容读取逻辑，但新曲库统一使用 audio/<专辑名>/。

## 曲名、音频标签和排序

扫描器先读音频文件的元数据标签。曲名优先使用标签中的 title；标签缺失或读取失败时，使用文件名并去除开头的曲目编号。还会读取 artist、albumArtist、album、year/date、genre、track、disc 和支持的同步内嵌歌词。

音频默认按碟号、曲目号、自然排序后的相对路径排列。未知曲目号排在已编号曲目之后。标签冲突时采用最常见值并写出扫描警告。

可重复曲名的 ID 会自动加入碟号、曲目号；如果仍然冲突，会用相对文件路径追加区分片段。为了让可选歌词或单曲图片唯一匹配，优先让对应文件名相同，并保留编号。若资源仍有歧义，扫描器会跳过可选资源并给出警告，不会随便绑定。

R2 同步器当前只接受小写英文字母、数字和连字符组成的 album ID 与 track ID。非 ASCII 曲名可能生成不被同步器接受的 ID。解决方式是让音频标签或文件名使用稳定的 ASCII 罗马化名称，并在 album.json 的 tracks 中用 title 覆盖最终显示名称；目录里仍可以放中文歌词和翻译。

## 添加第 13 张及以后

专辑数量没有 12 张的注册上限。放入新的直接子目录后，本地扫描器会发现它，CatalogProvider 按日期重新编号。Eras Corridor、EraIndex、播放器专辑轮播和背景轮换展示完整目录。圆柱每次页面加载最多从目录中随机抽取 12 张并保持目录顺序；超过 12 张时，新专辑会进入候选池，但某一次加载不保证抽中它。SpotlightEra 是独立的策划章节，不会因为新增专辑自动换成另一张专辑。

## 本地预览

在项目根目录运行：

~~~powershell
pnpm.cmd dev
~~~

打开终端显示的 Vite 地址。当前仓库把开发服务器固定在 http://localhost:5174，避免误开另一个窗口遗留的旧服务器；如果端口被占用，Vite 会报错退出，不会悄悄切换到别的页面。需要同时运行第二个开发服务器时，可执行 `pnpm.cmd dev --port 5180` 并打开终端实际显示的地址。Vite 会在启动时扫描 audio/；保存新的音频、album.json、LRC 或图片后会自动重新扫描。

没有本地曲目时，开发页面显示中英文空曲库说明。克隆仓库不会包含项目作者的个人音乐目录。请只添加自己有权使用的文件。

## 发布到 R2

先完成 [Cloudflare R2 配置](CLOUDFLARE_R2.md)，把凭证放在本地 .env.local，再执行：

~~~powershell
pnpm.cmd music:sync
~~~

同步器会先扫描整个 audio/，规划变更，增量上传变化的媒体并校验，再发布 Catalog。小型远端清理可能在发布 Catalog 后自动发生；大型清理、整张专辑删除或扫描警告会要求人工输入确认码。若不希望清理，取消本轮同步并先阅读 [MUSIC_SYNC.md](MUSIC_SYNC.md)。同步结束后刷新网站即可看到新 Catalog，不需要重新部署 Pages。
